# 종합 프로젝트 과제 — 세 가지 중 하나를 끝까지

> ⏱ 2~4주 · GPU 권장 · 선수 지식: 1~4부 전체

**목표:** 레슨을 따라 한 것과 스스로 만든 것의 차이는 **끝까지 가 본 경험**입니다. 아래 세 과제 중 하나를 골라 문제 정의부터 평가·보고까지 완주합니다. 각 과제에는 단계별 이정표, 제출물, 채점 기준이 있습니다. 혼자 공부하더라도 채점 기준표로 **스스로 채점**하세요.

## 공통 규칙

1. **문제를 한 문장으로 쓰고 시작합니다.** "입력은 ○○, 출력은 △△, 성공 기준은 □□(숫자)."
2. **평가 세트를 먼저 만듭니다.** 최소 50개. 학습에 절대 쓰지 않습니다. ([LLM 평가](#37-llm-eval))
3. **기준선을 잽니다.** 아무것도 안 한 모델 + 프롬프트의 점수가 첫 번째 결과입니다.
4. **실험 기록을 남깁니다.** 바꾼 것 하나, 결과 하나, 한 줄 메모. ([내 프로젝트 시작하기](#50-your-project)의 표)
5. **제출물은 셋입니다.** ① 실행 가능한 노트북(또는 코드 저장소), ② 평가 결과 표와 틀린 샘플 분석, ③ 2쪽 보고서(문제, 방법, 결과, 한계, 다음 단계).

## 과제 A: 내 문서 Q&A 봇 (RAG)

**문제:** 내가 고른 문서 묶음(강의 노트, 매뉴얼, 규정집, 위키 — 최소 30쪽 분량)에 대해 질문하면 문서에 근거해 답하고, 문서에 없으면 없다고 말하는 봇.

**바탕 레슨:** [임베딩과 RAG](#35-embeddings-rag), [LLM 다루기](#33-llm-inference), [LLM 평가](#37-llm-eval)

| 이정표 | 할 일 | 확인 |
|---|---|---|
| 1주 | 문서 수집·정리, 청킹(200~500자, 겹침 있음), 평가 질문 50개(답이 문서에 있는 것 40 + 없는 것 10)와 정답 문서 번호 | 평가 세트 완성 |
| 2주 | 임베딩 + 검색 구현. **검색 정확도**(정답 문서가 top-3에 있는 비율) 측정. 청크 크기·k·임베딩 모델을 바꿔 비교 | 검색 정확도 ≥ 0.8 |
| 3주 | LLM 연결, 프롬프트 설계, 거절 규칙. **답변 정확도**(포함 채점)와 **거절 정확도**(없는 질문에 "없다"고 하는 비율) | 두 지표 모두 기준선 대비 개선 |
| 4주 | 틀린 20개 분석(검색 실패 vs 생성 실패), 하이브리드 검색·리랭킹 중 하나 시도, 보고서 | 제출 |

**채점 기준 (100점)**

- 평가 세트의 질과 격리 (20): 질문이 실제 사용자 질문답고, 답이 문서에 있는지 명확하며, 학습·튜닝에 쓰이지 않음
- 검색 품질 측정과 개선 (25): 검색 정확도를 별도로 재고, 최소 두 가지 설정을 비교했으며, 개선 근거가 숫자로 있음
- 생성 품질과 거절 (20): 문서에 없는 질문을 지어내지 않고 거절하는 비율을 쟀고 개선했음
- 오류 분석 (20): 틀린 샘플을 검색 실패/생성 실패로 분류하고 각각의 원인과 대응을 썼음
- 재현성과 보고 (15): 노트북이 처음부터 끝까지 실행되고, 보고서에 한계와 다음 단계가 솔직히 적혀 있음

**흔한 실패:** 검색이 틀리는데 프롬프트만 계속 고치기. 답이 이상하면 **검색 결과부터** 보세요.

## 과제 B: 나만의 말투·역할 챗봇 (SFT + 선호 학습)

**문제:** 특정 역할(캐릭터, 상담원, 튜터)과 말투를 가진 챗봇. 지시 없이도 일관된 말투를 유지하되 **원래 능력(지식, 지시 따르기)이 망가지지 않아야** 합니다.

**바탕 레슨:** [LLM 파인튜닝](#34-llm-finetune), [DPO](#36-dpo), [LLM 평가](#37-llm-eval)

| 이정표 | 할 일 | 확인 |
|---|---|---|
| 1주 | 역할 정의서(말투 규칙 5개 이상), SFT 데이터 100~300쌍(직접 작성 또는 큰 모델로 생성 후 검수), 평가 세트: 말투 채점용 30문항 + **일반 능력 유지 확인용** 30문항(산수, 사실, 형식) | 데이터·평가 세트 완성 |
| 2주 | LoRA SFT. 에폭·r·학습률 3가지 이상 비교. 말투 점수(LLM 심사 또는 규칙 채점)와 일반 능력 점수를 **함께** 기록 | 말투↑, 일반 능력 하락 ≤ 5%p |
| 3주 | 선호 데이터 50쌍 이상 만들어 DPO. SFT만 한 것과 비교 | 어느 쪽이 나은지 근거 있는 결론 |
| 4주 | 실패 사례 분석(말투 깨짐, 능력 저하, 반복), 최종 모델 선택, 보고서 | 제출 |

**채점 기준 (100점)**

- 데이터 품질 (20): 말투 규칙이 명시되어 있고, 데이터가 그 규칙을 일관되게 따르며, 검수 흔적이 있음
- 이중 평가 (30): 말투와 일반 능력을 **둘 다** 재고, 트레이드오프를 표로 보였음
- 실험 설계 (20): 한 번에 하나씩 바꾼 비교 실험이 최소 3개, 결과가 기록됨
- 선호 학습의 효과 검증 (15): SFT 대비 DPO의 차이를 수치와 샘플로 보였음
- 재현성과 보고 (15)

**흔한 실패:** 말투 점수만 보고 "성공". 일반 능력 평가 없이는 catastrophic forgetting을 놓칩니다.

## 과제 C: 내 이미지 과제용 VLM (VLM 파인튜닝)

**문제:** 특정 종류의 이미지(영수증, 제품 사진, 식물, 손글씨 메모, 게임 화면 등)에 대해 정해진 질문에 정해진 형식으로 답하는 모델. 예: 영수증 → 총액·날짜 JSON, 제품 사진 → 불량 여부 예/아니오 + 이유.

**바탕 레슨:** [CLIP](#40-clip), [미니 VLM](#41-mini-vlm), [VLM 파인튜닝](#42-vlm-finetune), [LLM 평가](#37-llm-eval)

| 이정표 | 할 일 | 확인 |
|---|---|---|
| 1주 | 이미지 150장 이상 수집(직접 촬영 또는 공개 데이터), (이미지, 질문, 답) 라벨링, 학습/검증/평가 분할(100/25/25) | 데이터셋과 라벨 규칙 문서 |
| 2주 | 기준선: 사전학습 VLM + 프롬프트만으로 평가. CLIP 제로샷도 가능하면 비교 | 기준선 점수 |
| 3주 | LoRA 파인튜닝. text_model만 vs vision_model 포함, 데이터 50/100장 비교 | 기준선 대비 개선 |
| 4주 | 틀린 샘플 20개 분석(보는 문제 vs 말하는 문제), 실제 새 이미지 10장으로 최종 시험, 보고서 | 제출 |

**채점 기준 (100점)**

- 데이터와 라벨 규칙 (25): 라벨링 기준이 문서화되어 있고 애매한 경우의 처리 규칙이 있음. 분할이 이미지 단위로 겹치지 않음
- 기준선 대비 개선 (25): 프롬프트만 vs 파인튜닝 점수를 같은 평가 세트로 비교했음
- 학습 대상 선택의 근거 (15): 어느 부품에 LoRA를 붙였는지, 왜인지, 비교 결과
- 오류 분석 (20): 틀린 것을 "인식 실패"와 "형식/추론 실패"로 나누고 대응을 제안
- 재현성과 보고 (15)

**흔한 실패:** 평가 이미지가 학습 이미지와 같은 촬영 세션(같은 배경·조명)이라 점수가 부풀려짐. 평가 세트는 **다른 날, 다른 조건**에서 찍은 것으로.

## 보고서 양식 (2쪽)

1. **문제** — 한 문장 정의, 성공 기준, 왜 이 문제인가 (3~5줄)
2. **데이터** — 출처, 크기, 분할, 라벨 규칙, 평가 세트를 어떻게 격리했나
3. **방법** — 기준선, 시도한 것들(표), 최종 선택과 이유
4. **결과** — 지표 표(기준선 vs 최종), 대표 성공/실패 샘플 각 2개
5. **한계와 다음 단계** — 무엇이 안 됐고, 데이터·모델·시간이 더 있으면 무엇을 할지
6. **재현 방법** — 실행 순서, 소요 시간, 필요한 자원

## 핵심 정리
