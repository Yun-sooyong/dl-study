# 내 프로젝트 시작하기 — 실전 가이드

> ⏱ 30분 · 읽기 전용

**목표:** 레슨을 따라 하는 것과 내 문제를 푸는 것 사이의 간격을 메웁니다. 어떤 접근을 고를지, GPU가 얼마나 필요한지, 실험을 어떻게 굴릴지, 그다음엔 무엇을 공부할지 정리합니다.

## 1. 어떤 접근을 쓸 것인가

비싼 방법부터 시작하지 마세요. 아래 순서로 **싼 것부터** 시도하고, 안 될 때만 다음으로 갑니다.

| 순서 | 방법 | 필요한 것 | 이럴 때 |
|---|---|---|---|
| 1 | **프롬프트** (시스템 프롬프트, 퓨샷) | 예시 몇 개 | 거의 모든 경우의 출발점 → [LLM 다루기](#33-llm-inference) |
| 2 | **RAG** | 문서 | 모델이 **모르는 지식**이 필요할 때 → [임베딩과 RAG](#35-embeddings-rag) |
| 3 | **LoRA 파인튜닝 (SFT)** | (입력, 모범 출력) 수십~수천 쌍 | 말투·형식·좁은 과제의 **행동**을 바꿀 때 → [LLM 파인튜닝](#34-llm-finetune), [VLM 파인튜닝](#42-vlm-finetune) |
| 4 | **선호 학습 (DPO)** | (좋은 답, 나쁜 답) 쌍 | "더 나은" 쪽으로 미세 조정할 때 → [DPO](#36-dpo) |
| 5 | 전체 파인튜닝 / 추가 사전학습 | 대량의 데이터와 GPU | 새로운 언어·도메인 전체를 가르칠 때 |
| 6 | 처음부터 학습 | 막대한 데이터와 GPU | 연구 목적이거나 아주 작은 특수 모델 |

LLM이 필요 없는 문제도 많습니다. 표 데이터 예측은 [트리 모델](#12-ml-tabular-trees), 이미지 분류는 [전이학습](#25-transfer-learning)이 더 싸고 정확합니다.

## 2. 프로젝트 진행 순서

1. **문제를 한 문장으로 쓴다.** "입력은 ○○, 출력은 △△, 성공 기준은 □□." 성공 기준을 숫자로 못 쓰겠다면 아직 시작할 때가 아닙니다.
2. **평가 세트를 먼저 만든다.** 학습 데이터보다 먼저, 50~200개의 (입력, 기대 출력)을 직접 만들고 따로 떼어 둡니다. 이것이 프로젝트의 나침반입니다.
3. **기준선을 잰다.** 아무것도 안 한 기본 모델 + 간단한 프롬프트의 점수. 이보다 나아져야 의미가 있습니다.
4. **데이터를 눈으로 본다.** 100개쯤 직접 읽습니다. 라벨 오류, 중복, 형식 불일치를 고치는 것이 모델을 바꾸는 것보다 효과가 큰 경우가 대부분입니다.
5. **작게 시작한다.** 가장 작은 모델, 데이터 일부로 파이프라인 전체(로딩 → 학습 → 평가 → 저장)를 먼저 끝까지 돌립니다. "배치 하나 외우기"로 버그를 잡습니다 → [학습 잘 시키는 법](#24-training-recipes).
6. **한 번에 하나만 바꾼다.** 학습률, 데이터 양, 모델 크기, LoRA rank… 하나씩 바꾸고 결과를 기록합니다.
7. **틀린 것을 읽는다.** 점수만 보지 말고 모델이 틀린 샘플 20개를 직접 읽으세요. 다음에 무엇을 해야 할지는 거기에 적혀 있습니다.

## 3. 실험 기록

일주일 뒤의 나는 오늘의 실험을 기억하지 못합니다. 최소한 아래를 표로 남기세요(스프레드시트면 충분합니다).

| 날짜 | 바꾼 것 | 설정 (모델, lr, 에폭, 데이터 수) | val 점수 | 메모 |
|---|---|---|---|---|
| 9/18 | 기준선 | Qwen2.5-0.5B, 프롬프트만 | 61% | 형식 오류가 대부분 |
| 9/18 | LoRA r=8 | lr 2e-4, 3ep, 200개 | 78% | 긴 입력에서 실패 |

실험이 많아지면 `wandb`나 `tensorboard`로 loss 곡선을 자동 기록합니다. 시드 고정(`torch.manual_seed`)과 설정값 저장도 습관으로 만드세요.

## 4. GPU 메모리 어림 계산

모델이 GPU에 올라가는지는 대략 계산할 수 있습니다. 파라미터 1개가 차지하는 바이트: fp32는 4, fp16/bf16은 2, 8비트는 1, 4비트는 0.5.

| 하려는 일 | 필요 메모리(대략) | 7B 모델 예 |
|---|---|---|
| 추론 (fp16) | 파라미터 수 × 2바이트 + KV 캐시 | 약 14GB + α |
| 추론 (4비트 양자화) | 파라미터 수 × 0.5바이트 | 약 4GB + α |
| 전체 파인튜닝 (AdamW, 혼합 정밀도) | 파라미터 수 × 약 16바이트 + 활성값 | 약 112GB 이상 |
| LoRA (fp16 베이스) | 파라미터 수 × 2바이트 + 활성값 + 약간 | 약 16~20GB |
| QLoRA (4비트 베이스) | 파라미터 수 × 0.5바이트 + 활성값 + 약간 | 약 6~10GB |

- 전체 파인튜닝이 비싼 이유: 가중치 외에 **기울기**와 옵티마이저 상태(Adam은 파라미터당 값 2개)를 모두 들고 있어야 합니다. LoRA는 그것들이 어댑터 크기만큼만 필요합니다.
- **활성값** 메모리는 배치 크기 × 시퀀스 길이에 비례합니다. 메모리가 부족하면(`CUDA out of memory`) 배치 크기를 줄이고 그래디언트 누적을 쓰고, 시퀀스 길이를 줄이고, gradient checkpointing을 켭니다.
- Colab 무료 T4는 16GB입니다. 이 코스의 0.5B 모델은 fp32로도 여유 있고, QLoRA를 쓰면 7B급까지 파인튜닝할 수 있습니다.

## 5. 모델 고르기

[Hugging Face Hub](https://huggingface.co/models)에서 고를 때 볼 것:

- **크기:** 내 GPU에 올라가는 가장 큰 것이 아니라, 과제를 해결하는 **가장 작은 것**. 작을수록 실험이 빠르고 서비스 비용이 쌉니다.
- **Base vs Instruct:** 대화·지시 수행이 목적이면 Instruct에서 출발합니다.
- **언어:** 한국어 성능과 토큰 효율을 직접 확인하세요 → [토크나이저](#30-tokenizer).
- **라이선스:** 상업적 이용 가능 여부가 모델마다 다릅니다.
- **모델 카드:** 권장 프롬프트 형식, 전처리, 알려진 한계가 적혀 있습니다. 꼭 읽으세요.

2026년 기준으로 입문용으로 다루기 좋은 공개 모델 계열: Qwen, Llama, Gemma, SmolLM(언어) / SmolVLM, Qwen-VL, InternVL(비전-언어) / bge, e5(임베딩). 모델은 빠르게 바뀌므로 이름보다 **고르는 기준**을 기억하세요.

## 6. 직접 짠 루프에서 도구로

이 코스는 원리를 보이려고 학습 루프를 직접 짰습니다. 실전에서는 아래 도구들이 같은 일을 더 안전하게 해 줍니다. 안에서 벌어지는 일은 이제 전부 아는 내용입니다.

| 도구 | 하는 일 |
|---|---|
| `transformers.Trainer` | 학습 루프, 체크포인트, 로깅, 혼합 정밀도, 그래디언트 누적, 멀티 GPU |
| `trl` (`SFTTrainer`, `DPOTrainer`) | LLM SFT·선호 학습 전용 Trainer. 라벨 마스킹, 채팅 템플릿 처리 포함 |
| `peft` + `bitsandbytes` | LoRA / QLoRA (4비트 양자화) |
| `datasets` | 대용량 데이터 로딩·전처리·공유 |
| `vLLM`, `llama.cpp`, `Ollama` | 학습한 모델을 빠르게 서빙 / 내 컴퓨터에서 실행 |
| `wandb`, `tensorboard` | 실험 기록과 시각화 |

## 7. 프로젝트 아이디어

쉬운 것부터:

- **나만의 말투 챗봇:** 내 메신저 말투, 좋아하는 캐릭터 말투로 LoRA 파인튜닝.
- **내 문서 Q&A:** 수업 노트·매뉴얼·회사 위키로 RAG 봇 만들기. 검색 정확도를 숫자로 재 보기.
- **리뷰/문의 분류기:** 퓨샷 프롬프트 vs 파인튜닝 vs 임베딩+로지스틱 회귀를 같은 평가 세트로 비교.
- **사진 검색기:** CLIP으로 내 사진첩을 문장으로 검색.
- **특정 이미지 판독 VLM:** 영수증 항목 추출, 제품 불량 판정, 식물 상태 설명 등 (이미지, 질문, 답) 100쌍으로 VLM LoRA.
- **미니 GPT 확장:** 한국어 데이터로 학습, BPE 토크나이저 붙이기, 모델을 키우며 loss가 어떻게 줄어드는지(스케일링) 그려 보기.

## 핵심 정리

- 프롬프트 → RAG → LoRA → 선호 학습 순으로, **싼 방법부터** 시도합니다.
- 학습 데이터보다 **평가 세트를 먼저** 만들고, 기준선을 재고, 한 번에 하나만 바꿉니다.
- 데이터를 직접 읽고, 틀린 샘플을 직접 읽습니다.
- 메모리 어림: 추론은 파라미터 × 2바이트, 전체 학습은 × 16바이트, LoRA/QLoRA로 크게 줄일 수 있습니다.
- 과제를 해결하는 가장 작은 모델이 가장 좋은 모델입니다.

<details><summary>Q1. 고객 문의에 회사 환불 규정대로 답하는 챗봇을 만들려 합니다. 무엇부터 시도하겠습니까?</summary>

규정은 **지식**이고 자주 바뀔 수 있으므로 RAG가 기본입니다(규정 문서 검색 → 프롬프트에 포함). 말투나 답변 형식이 프롬프트로 안 잡힐 때에만 소량의 SFT를 추가합니다. 그 전에 실제 문의 100개로 평가 세트부터 만듭니다.

</details>

<details><summary>Q2. 16GB GPU에서 7B 모델을 파인튜닝할 수 있나요?</summary>

전체 파인튜닝은 불가능합니다(100GB 이상 필요). 4비트로 양자화한 베이스 위에 LoRA를 학습하는 QLoRA라면 배치 크기와 시퀀스 길이를 작게 잡아 가능합니다.

</details>

<details><summary>Q3. 파인튜닝 후 val 점수가 올랐습니다. 배포 전에 더 확인할 것은?</summary>

① 한 번도 쓰지 않은 test 세트 점수, ② 학습시키지 않은 다른 능력이 망가지지 않았는지(catastrophic forgetting), ③ 틀린 샘플을 직접 읽어 위험한 실패 유형이 없는지, ④ 실제 입력 분포(길이, 말투, 오타)에서의 동작.

</details>
