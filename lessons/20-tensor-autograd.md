# 텐서와 자동미분 — 학습이란 무엇인가

> ⏱ 40분 · CPU로 충분 · 선수 지식: 파이썬 기초

**목표:** "모델을 학습시킨다"가 실제로 어떤 계산인지, 가장 작은 예제로 손에 익힙니다.

## 텐서: 숫자가 담긴 다차원 배열

딥러닝의 모든 데이터(이미지, 글, 모델의 가중치)는 텐서입니다.

```python
import torch

x = torch.tensor([[1., 2., 3.],
                  [4., 5., 6.]])
print(x.shape)        # torch.Size([2, 3]) — 2행 3열
print(x * 2)          # 원소별 연산
print(x @ x.T)        # 행렬곱: (2,3) @ (3,2) = (2,2)
print(x.mean(dim=0))  # 0번 축(행)을 따라 평균 → 길이 3
```

**코드 읽기**

- 왜 PyTorch인가: 1부의 scikit-learn은 "완성된 모델"을 골라 쓰는 도구입니다. 모델의 **내부를 직접 만들려면** 행렬 계산과 자동미분을 제공하는 프레임워크가 필요하고, 연구·산업 양쪽에서 가장 널리 쓰이는 것이 PyTorch입니다. Hugging Face의 LLM들도 PyTorch 위에서 돌아갑니다.
- `torch.tensor([[1., 2., 3.], ...])` — 숫자 뒤의 `.`은 **실수(float)** 로 만들기 위한 것입니다. 정수 텐서는 미분을 할 수 없어서(기울기는 연속량), 학습에 쓰는 텐서는 거의 항상 실수입니다.
- `x.shape` — numpy와 같은 개념. `torch.Size([2, 3])`은 2행 3열. 앞으로 모든 오류의 절반은 이 값을 찍어 보면 풀립니다.
- `x @ x.T` — `@`는 행렬곱. 신경망의 층 하나가 하는 계산이 바로 행렬곱이라서, 이 연산이 딥러닝 계산의 90% 이상을 차지합니다. GPU가 필요한 이유도 행렬곱을 병렬로 빨리 하기 때문입니다.
- `x.mean(dim=0)` — `dim`은 "어느 축을 없애면서 계산하나"입니다. `dim=0`은 행 방향으로 뭉개서 열마다 평균 하나(길이 3), `dim=1`이면 행마다 평균 하나(길이 2). 배치 전체의 평균 손실을 구할 때 등 계속 나옵니다.
## 자동미분: PyTorch의 핵심

`requires_grad=True`인 텐서로 계산하면, PyTorch가 계산 과정을 기록해 두었다가 `backward()` 한 번에 미분값을 구해줍니다.

```python
w = torch.tensor(3.0, requires_grad=True)
y = w ** 2 + 2 * w    # y = w² + 2w
y.backward()          # dy/dw 계산
print(w.grad)         # 2w + 2 = 8
```

기울기(gradient)는 "w를 조금 키우면 y가 얼마나 변하나"입니다. 손실의 기울기를 알면, **반대 방향으로 조금 움직여서 손실을 줄일 수 있습니다.** 이것이 학습의 전부입니다.

**코드 읽기**

- `requires_grad=True` — "이 텐서에 대한 미분값이 필요하다"는 표시. 이 표시가 있는 텐서가 관여한 모든 계산을 PyTorch가 뒤에서 **계산 그래프**로 기록합니다. 학습할 파라미터에만 붙이고, 입력 데이터에는 붙이지 않습니다(데이터를 바꿀 게 아니니까).
- `y.backward()` — 기록된 그래프를 거꾸로 따라가며 `y`를 각 파라미터로 미분한 값을 구해 `.grad`에 채워 넣습니다. 손으로 미분식을 유도할 필요가 없다는 것이 핵심입니다. 수백만 개 파라미터를 가진 모델도 이 한 줄이면 됩니다. 수식으로 미분하는 게 아니라 **연쇄법칙을 수치적으로 적용**하는 것이라, 아무리 복잡한 계산이라도 됩니다.
- `w.grad` — 결과가 저장되는 곳. 이 예에서는 `dy/dw = 2w + 2 = 8`이 정확히 나옵니다. 자동미분이 "근사"가 아니라 "정확한 미분"임을 확인하는 셈입니다.

## 직접 학습시켜 보기: 직선 맞추기

정답이 `y = 2x + 1`인 데이터를 만들고, 모델이 `w=2, b=1`을 스스로 찾아내게 합니다.

```python
torch.manual_seed(0)
X = torch.rand(100, 1) * 10
Y = 2 * X + 1 + torch.randn(100, 1) * 0.5   # 약간의 노이즈

w = torch.zeros(1, requires_grad=True)   # 학습할 파라미터. 0에서 시작
b = torch.zeros(1, requires_grad=True)
lr = 0.01                                # 학습률: 한 번에 얼마나 움직일지

for step in range(1000):
    pred = X * w + b                     # 1) 예측
    loss = ((pred - Y) ** 2).mean()      # 2) 손실 (평균제곱오차)
    loss.backward()                      # 3) 기울기 계산
    with torch.no_grad():                # 4) 파라미터 갱신 (이 계산은 기록하지 않음)
        w -= lr * w.grad
        b -= lr * b.grad
        w.grad.zero_()                   # 기울기는 누적되므로 매번 0으로 초기화
        b.grad.zero_()
    if step % 200 == 0:
        print(f"step {step:4d}  loss {loss.item():.4f}  w {w.item():.3f}  b {b.item():.3f}")

print(f"결과: w={w.item():.3f} (정답 2), b={b.item():.3f} (정답 1)")
```

데이터에 노이즈를 섞었기 때문에 정확히 2와 1이 나오지는 않습니다. 모델은 "주어진 데이터에 가장 잘 맞는" 값을 찾을 뿐입니다.

**코드 읽기** — 이 스무 줄이 이 코스의 뼈대입니다. 한 줄씩 보세요.

- `torch.manual_seed(0)` — 이후의 `torch.rand`, `torch.randn`이 매번 같은 값을 내도록 고정. 실험 비교의 전제 조건입니다.
- `X = torch.rand(100, 1) * 10` — 0~10 사이 입력 100개를 `(100, 1)` 모양으로. 1열인 이유는 "샘플 100개 × 특징 1개"라는 2차원 규칙을 지키기 위해서입니다(1부의 `x[:, None]`과 같은 이유).
- `torch.randn(100, 1) * 0.5` — 표준정규분포 노이즈에 0.5를 곱해 크기 조절. 현실 데이터의 잡음을 흉내 냅니다.
- `w = torch.zeros(1, requires_grad=True)` — 파라미터를 0에서 시작. 이 값은 뭐든 상관없습니다. 학습이 알아서 옮겨 갑니다. 신경망에서는 0 대신 작은 난수로 시작하는데, 그 이유는 다음 레슨에서 나옵니다.
- `lr = 0.01` — 학습률. 기울기가 알려주는 것은 **방향**뿐이고, 얼마나 갈지는 이 값이 정합니다.
- `pred = X * w + b` — 모델. 지금은 직선 하나이지만, 여기가 나중에 `model(x)`로 바뀝니다.
- `loss = ((pred - Y) ** 2).mean()` — 평균제곱오차(MSE). 왜 제곱인가: 부호를 없애면서(양쪽 오차 모두 벌점) 미분이 매끄럽고, 큰 오차에 더 큰 벌을 줍니다. `.mean()`으로 샘플 100개의 오차를 숫자 하나로 요약해야 `backward()`를 할 수 있습니다(미분은 스칼라에서 출발).
- `loss.backward()` — `w.grad`, `b.grad`가 채워집니다.
- `with torch.no_grad():` — 이 블록 안의 계산은 그래프에 기록하지 말라는 뜻. 파라미터를 갱신하는 `w -= ...`는 학습의 일부이지 모델 계산이 아니므로 기록하면 안 됩니다(기록하면 그래프가 무한히 자라고 에러가 납니다).
- `w -= lr * w.grad` — 경사하강법 한 걸음. 기울기의 **반대 방향**(빼기)으로 학습률만큼.
- `w.grad.zero_()` — 기울기를 0으로 리셋. PyTorch는 `backward()`를 부를 때마다 `.grad`에 **더해** 넣습니다(여러 손실을 합칠 때 편하도록 설계된 것). 리셋하지 않으면 지난 스텝의 기울기가 계속 누적되어 엉뚱한 방향으로 갑니다. 끝의 `_`는 "제자리에서 바꾼다(in-place)"는 PyTorch의 이름 규칙입니다.
- `loss.item()` — 텐서 안의 숫자 하나를 파이썬 float로 꺼냅니다. 출력이나 기록용. 텐서를 그대로 리스트에 모으면 그래프까지 붙어 와서 메모리가 샙니다.

## 같은 일을 PyTorch 도구로

위의 수작업을 `nn.Linear`(파라미터 묶음), `optim.SGD`(갱신 규칙)가 대신해 줍니다. **구조는 완전히 같습니다.** 앞으로 모든 레슨이 이 모양입니다.

```python
from torch import nn

model = nn.Linear(1, 1)                                  # w와 b를 가진 층
optimizer = torch.optim.SGD(model.parameters(), lr=0.01)
loss_fn = nn.MSELoss()

for step in range(1000):
    loss = loss_fn(model(X), Y)
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()

print(model.weight.item(), model.bias.item())
```

**코드 읽기** — 위의 수작업 코드와 한 줄씩 짝지어 보세요.

- `nn.Linear(1, 1)` — "입력 1개 → 출력 1개"인 층. 안에 `weight`(w)와 `bias`(b)를 `requires_grad=True`로 만들어 갖고 있고, `model(X)`를 부르면 `X @ weight.T + bias`를 계산합니다. 즉 위의 `X * w + b`를 클래스로 포장한 것입니다. 왜 포장하나: 파라미터가 수백만 개가 되면 하나하나 변수로 만들 수 없기 때문입니다.
- `model.parameters()` — 모델 안의 모든 학습 대상 텐서를 돌려줍니다. 옵티마이저에 "이것들을 갱신하라"고 넘기는 용도입니다.
- `torch.optim.SGD(params, lr=0.01)` — 위의 `w -= lr * w.grad`를 대신하는 객체. **S**tochastic **G**radient **D**escent, 즉 경사하강법 그 자체입니다. 이름의 "확률적"은 데이터 일부(배치)만으로 기울기를 구해도 된다는 뜻입니다.
- `nn.MSELoss()` — `((pred - Y) ** 2).mean()`을 대신합니다. 손실 함수를 객체로 두면 나중에 `CrossEntropyLoss`로 갈아끼우기만 하면 됩니다.
- `optimizer.zero_grad()` — 모든 파라미터의 `.grad`를 0으로. `w.grad.zero_(); b.grad.zero_()`를 한 줄로.
- `optimizer.step()` — 모든 파라미터에 대해 `p -= lr * p.grad`. `with torch.no_grad()`도 안에서 알아서 처리합니다.
- 순서가 `zero_grad → backward → step`인 것에 주의하세요. `backward` 전에 기울기를 비우고, `backward`로 새 기울기를 구하고, `step`으로 적용합니다. 앞으로 모든 학습 루프가 이 세 줄입니다.
## 핵심 정리

- 학습 = **손실을 줄이는 방향으로 파라미터를 조금씩 옮기는 것**. 방향은 기울기가 알려줍니다.
- `loss.backward()`가 모든 파라미터의 기울기를 계산하고, `optimizer.step()`이 파라미터를 갱신합니다.
- 기울기는 누적되므로 매 스텝 `zero_grad()`가 필요합니다.
- 학습률이 너무 크면 발산하고, 너무 작으면 느립니다.
- `예측 → 손실 → backward → step` 네 줄은 이 코스 끝까지 그대로 나옵니다.

## 스스로 점검

답을 머릿속으로 먼저 말해 본 뒤 펼쳐 보세요.

<details><summary>Q1. <code>requires_grad=True</code>는 무엇을 하라는 표시인가요?</summary>

이 텐서가 관여한 계산을 기록해 두었다가, `backward()` 때 이 텐서에 대한 기울기를 구해 `.grad`에 넣으라는 표시입니다. 학습할 파라미터에 붙입니다.

</details>

<details><summary>Q2. 파라미터를 갱신할 때 왜 기울기를 <b>빼나요</b>?</summary>

기울기는 손실이 **커지는** 방향입니다. 손실을 줄이려면 반대 방향으로 가야 하므로 `w -= lr * w.grad`입니다.

</details>

<details><summary>Q3. 직선 모델로 <code>y = 3x² + 1</code> 데이터를 잘 못 맞히는 이유는?</summary>

모델이 표현할 수 있는 함수가 직선뿐이기 때문입니다(과소적합). 더 복잡한 관계를 배우려면 층을 쌓고 비선형 활성화 함수를 넣어야 합니다.

</details>
